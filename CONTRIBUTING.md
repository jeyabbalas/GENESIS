# Contributing

Bug reports, questions and pull requests are welcome at
<https://github.com/jeyabbalas/GENESIS>.

## Reporting a problem

Please open an [issue](https://github.com/jeyabbalas/GENESIS/issues) and include

- the output of `genesis doctor` (versions, CPUs/GPUs, backend self-test);
- the exact command or script;
- the log file written by `genesis fit` (`PREFIX.log`), or the full traceback obtained
  with `--debug`;
- for unexpected estimates: the result file (`PREFIX.M2.json` / `PREFIX.M3.json`). It
  contains the settings, the QC report and the diagnostics, and no individual-level
  data.

Do not attach summary statistics that you are not allowed to share.

## Development setup

The project uses a `src` layout and [hatchling](https://hatch.pypa.io/). With
[uv](https://docs.astral.sh/uv/):

```bash
git clone https://github.com/jeyabbalas/GENESIS.git
cd GENESIS
uv venv --python 3.12
uv pip install -e ".[dev,docs]"
uv pip install torch          # optional: enables the PyTorch backend tests
source .venv/bin/activate
```

(`python -m venv .venv && pip install -e ".[dev,docs]"` works equally well.)

## Checks

All of the following run in continuous integration (`.github/workflows/ci.yml`) and
must pass:

```bash
ruff check src tests            # lint (includes numpydoc-style docstring rules)
ruff format --check src tests   # formatting; `ruff format src tests` to apply
mypy                            # static types (configuration in pyproject.toml)
pytest -q                       # tests that need no external data (a few minutes)
pytest -q -m "not slow"         # what CI runs
```

Tests that need external data are skipped unless the data are present:

```bash
# Genome-wide parity with the original software (needs the full reference bundle)
genesis data fetch --components default,examples --dest /path/to/data
GENESIS_DATA_DIR=/path/to/data pytest tests/test_full_scale.py
# ... and with GENESISasian (East Asian reference with null replicates and pairwise r2)
genesis data fetch EAS --components default,nullz,pairld --dest /path/to/data

# LD builder against the original reference tables (needs the LDSC 1000 Genomes EUR PLINK files)
GENESIS_1000G_PLINK=/path/to/1000G_EUR_Phase3_plink pytest tests/ld
```

Markers: `slow`, `torch`, `gpu` (needs a CUDA device), `mps`, `refdata`.

## Documentation

The site is built with Sphinx (MyST Markdown, Furo theme):

```bash
sphinx-build -W --keep-going -b html docs docs/_build/html
python -m http.server -d docs/_build/html 8000      # then open http://localhost:8000
```

`-W` turns warnings into errors, as in the deployment workflow
(`.github/workflows/docs.yml`). The API reference is generated from the docstrings
(numpydoc style) and the command-line reference from the argument parser, so a change
to a signature or an option needs no separate documentation edit — but a new public
function has to be listed on the appropriate page under `docs/api/`.

Figures of the tutorial are produced by the scripts in `docs/_scripts/`.

## Conventions

- **Tests come with the change.** New behaviour needs a test; a bug fix needs a test
  that fails without it.
- **Numerical changes need evidence.** The fitting code is tested against outputs of
  the original R/C++ implementation (`tests/fixtures/upstream`, generated by
  `tools/upstream_oracle`; see its README for how to regenerate them, which requires R
  and a clone of the original repository) and against a literal port of the original
  C++ (`tests/upstream_port.py`). `legacy=True` must keep reproducing those fixtures.
  Any intended difference from the original belongs in
  `docs/reference/differences.md` with its reason and measured effect.
- **One implementation of the kernels.** Numerical code in `genesis_gwas.core.kernels`
  is written against the small array interface in `genesis_gwas.backends` so that the
  NumPy and PyTorch backends cannot drift apart; do not add backend-specific
  mathematics elsewhere.
- **Double precision everywhere**, including on GPUs.
- **Errors are explicit.** Raise a subclass of `GenesisError` with a message that says
  what to do; use the warning classes in `genesis_gwas.exceptions` for conditions the
  analyst must see, and add them to the result's `warnings`.
- **Public API**: objects are exported from `genesis_gwas/__init__.py`; changes to
  them, to the command line or to the result-file schema go into `CHANGELOG.md`.
- **Style**: `ruff` (line length 100), type annotations on all functions, numpydoc
  docstrings with the mathematics in LaTeX where it helps.
- **Do not commit data.** Reference bundles are release assets; manuscripts and other
  third-party material are not redistributable (`reference/` is ignored by git).

## Releasing

1. Update `src/genesis_gwas/_version.py`, `CHANGELOG.md` and `CITATION.cff`.
2. Tag `vX.Y.Z` and push the tag; pushing to `main` deploys the documentation.
3. Reference data are versioned separately (release tag `refdata-v1`); a new bundle
   needs a new manifest in `src/genesis_gwas/data/manifests/` and a new tag.
